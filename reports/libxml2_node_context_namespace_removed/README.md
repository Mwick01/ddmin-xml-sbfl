**Removing the manually attached namespace gives PASS cases, but also removes the failing starting condition for this bug.**

The HTML document, root node, fragment parsing call and libxml2 source revisions were held constant. The experimental driver change removes the `xmlNewNs(root, "urn:probe", "p")` block and its unused variable. This is a driver/context change, not a patch to the buggy library.

Both probes were compiled against libxml2 v2.12.4 (buggy) and v2.12.5 (fixed), with identical build options. The original-context control reproduced SIGSEGV 10/10 times on the buggy version, while the fixed version accepted. With the namespace removed, the same fragment was accepted by both versions 10/10 times.

The paired replay evaluates exactly the candidates generated by original-context DDMIN under the changed context. It is a replay, not a second successful DDMIN run. The fresh 24-fragment screen is explicitly new: the old report preserved counts and examples but not its full 24-fragment corpus. The supplementary screen tests every contiguous substring and contiguous-block deletion of the seed; it is diagnostic screening, not DDMIN.

Oracle: fixed probe must exit normally with `result=0`. A buggy SIGSEGV then means FAIL. If the buggy probe also exits normally with `result=0` and the same result/list summary, the case is PASS. Invalid fragments, other errors and timeouts are UNRESOLVED. The unchanged C probe does not serialize full output trees, so PASS here measures agreement of acceptance and the available result/list summary.

This confirms that the namespace attachment is part of the triggering setup. The namespace-free fixed-context experiment has passing examples but no failing seed in the tested inputs. A joint context-plus-fragment experiment would be needed to investigate whether both outcomes can be obtained within a single mutable input model.
