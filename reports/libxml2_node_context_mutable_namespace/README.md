The seed was:

```xml
<case xmlns:p="urn:probe"><span>probe</span></case>
```

The following pair occurred among the actual DDMIN candidates. Both produce the same fragment `&gt;`:

FAIL:

```xml
<case xmlns:p="u">></case>
```

PASS:

```xml
<case xmlnsp="u">></case>
```

Deleting the colon from `xmlns:p` makes `xmlnsp` an ordinary attribute. The driver therefore attaches no namespace in the PASS case. The URI value and parsed fragment are otherwise identical in this pair. This is a one-character change generated by the unchanged character reducer.

The FAIL example is the run's minimal failure. It reproduced the buggy SIGSEGV and fixed acceptance 10/10 times. A PASS example from DDMIN was accepted by both versions 10/10 times. Before reduction, the original namespace-bearing seed failed 10/10 times, while a version with its namespace declaration removed passed 10/10 times. These reliability checks and controls are excluded from the DDMIN candidate counts.

A separate check removed the namespace declaration from the minimal FAIL while keeping its fragment unchanged:

```xml
<case>&gt;</case>
```

That case was PASS. It is a targeted post-run check, not an additional DDMIN-generated candidate.

Input model and driver:

- The input is one XML test envelope. Its root namespace declarations configure the HTML context; its serialized child nodes form the fragment passed to `xmlParseInNodeContext`.
- The same Python standard-library XML decoder reads each candidate once and supplies identical arguments to both target versions. Envelope decoding therefore does not use different libxml2 versions.
- The outer element's name and ordinary attributes are envelope metadata and do not configure the context. Namespace URI/prefix values come entirely from the input. Empty namespace undeclarations attach no namespace.
- The HTML document and context node stay fixed as in the historical probe. The C driver calls `xmlNewNs` for the input-derived declarations, then calls `xmlParseInNodeContext`. The libxml2 sources are unchanged.
- All input characters can be deleted by DDMIN. No structural reducer, namespace toggle flag, oracle relabeling, or failing-input-guard bypass was used.

Oracle:

- FAIL: v2.12.5 accepts the fragment (`result=0`) and v2.12.4 dies with SIGSEGV.
- PASS: both probes exit normally, accept the fragment and print equal result/list summaries.
- UNRESOLVED: the envelope cannot be decoded, the fixed probe rejects the fragment, or another execution error/timeout occurs.

Of the 149 UNRESOLVED cases, 148 failed envelope XML decoding and 1 reached the probes. The probe reports acceptance and list presence; it does not compare fully serialized output trees.

The libraries are the previously rebuilt v2.12.4/v2.12.5 static libraries with verified matching hashes. The reducer is a byte-for-byte copy of `scripts/ddmin.py` at experiment commit `28b33554441e7fafe4a8f9f3b61f6b894b839c6c`.

This result establishes a PASS/FAIL boundary for the expanded context-plus-fragment input model. It does not change the earlier fragment-only screening result, and the counts are not a direct comparison with that earlier input domain. Coverage, fault ranks, fuzzing and formal SBFL suitability have not been evaluated in this run.
